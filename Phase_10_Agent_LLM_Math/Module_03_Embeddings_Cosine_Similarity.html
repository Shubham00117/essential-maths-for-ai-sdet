Cosine Similarity: Angle > Distance

🧠 Why angle, not Euclidean distance?

Problem with distance: Longer vectors have bigger distances even if pointing same direction

Solution - Use angle: Angle only cares about direction = pure meaning comparison

Result: Value between -1 and 1
• 1 = identical direction (same meaning)
• 0 = perpendicular (unrelated)
• -1 = opposite (antonyms)
cos(θ) = (A · B) / (||A|| × ||B||)

= (dot product) / (magnitude A × magnitude B)
cos = 1.0Same direction
Identical meaning
cos = 0.0Perpendicular
Unrelated
cos = -1.0Opposite
Contradictory

5️⃣ Logical Flow (How RAG Thinks)

How Vector Search Works

STEP 1: EMBEDDING GENERATION User query: "How do I train a neural network?" → Convert to vector: [0.2, 0.8, -0.1, ..., 0.5] (384-1536 numbers) STEP 2: STORE DOCUMENTS (done beforehand) Each document → also converted to vector Store: (doc_id, doc_text, doc_vector) STEP 3: SIMILARITY SEARCH For each stored document: Calculate: cosine_sim(query_vector, doc_vector) Sort by similarity (highest first) STEP 4: THRESHOLD FILTER Keep only docs where similarity >= 0.75 (or your threshold) STEP 5: RETURN TOP-K Return top 3-5 most similar documents

Cosine Similarity Calculation Logic

GIVEN: Two vectors A and B (same length) STEP 1: DOT PRODUCT Multiply corresponding elements, sum all dot = A[0]*B[0] + A[1]*B[1] + ... + A[n]*B[n] STEP 2: MAGNITUDES mag_A = sqrt(A[0]² + A[1]² + ... + A[n]²) mag_B = sqrt(B[0]² + B[1]² + ... + B[n]²) STEP 3: DIVIDE cosine_similarity = dot / (mag_A × mag_B) RESULT: Number between -1 and 1 OPTIMIZATION: If vectors are pre-normalized (length=1): cosine_similarity = just the dot product! (This is why RAG systems normalize vectors on insert)

RAG Relevance Decision

INPUTS: - query_embedding (from user question) - retrieved_docs (from vector search) - threshold = 0.75 - min_docs = 1 LOGIC: relevant_docs = [] FOR each doc in retrieved_docs: sim = cosine_similarity(query_embedding, doc.embedding) IF sim >= threshold: relevant_docs.append(doc) IF len(relevant_docs) < min_docs: DECISION: "Not enough relevant context" ACTION: Use LLM knowledge only (no RAG augmentation) ELSE: DECISION: "Good context found" ACTION: Include relevant_docs in LLM prompt

6️⃣ AI / GenAI Application

RAG Pipeline with Embeddings:

User Query: "What is machine learning?"
        ↓
    [EMBED QUERY] → Vector: [0.3, 0.7, -0.2, ...]
        ↓
    [VECTOR SEARCH] → Find similar doc vectors
        ↓
    [RANK BY SIMILARITY]
        Doc A: 0.92 similarity ✅
        Doc B: 0.85 similarity ✅
        Doc C: 0.65 similarity ❌ (below threshold)
        ↓
    [FILTER BY THRESHOLD] → Keep A, B
        ↓
    [AUGMENT PROMPT] → "Context: Doc A, Doc B" + Query
        ↓
    [LLM GENERATES] → Answer with context
🎯 The Core Insight for RAG:

1. Similar meaning → Similar vectors → High cosine similarity
2. Find documents where cosine(query, doc) > threshold
3. Use those documents as context for LLM
4. LLM generates answer using retrieved context

That's semantic search! Pure math + pure meaning.

7️⃣ Testing / SDET Angle

🧪 Testing Embedding-Based Systems

Test Type What to Verify
Self-Similarity cosine(A, A) must equal 1.0
Symmetry cosine(A, B) must equal cosine(B, A)
Bounds Result must be between -1 and 1
Known Pairs cosine("dog", "puppy") should be > 0.8
Threshold Edge Test at 0.799 vs 0.801 with 0.8 threshold
Zero Vector Handle gracefully, don't divide by zero
Normalization After normalizing, vector length should ≈ 1.0

8️⃣ Common Mistakes

❌ Using Euclidean distance instead of cosine: Distance doesn't normalize for vector length!
❌ Wrong threshold intuition: 0.5 is NOT "50% similar" — in embedding space, it's actually quite low!
❌ Not normalizing vectors: Pre-normalize for faster repeated comparisons
❌ Comparing different embedding models: OpenAI ≠ sentence-transformers — dimensions and spaces differ!
❌ Ignoring zero vectors: Always check for zero magnitude before dividing

9️⃣ One-Line Summary

💡 Embeddings turn meaning into numbers, cosine similarity measures how aligned those meanings are — this is the heart of RAG and semantic search.
