⚡ Module 04: Optimization Thinking & Model Economics

1️⃣ Topic: Optimization for AI Systems

Optimization Thinking = Making smart trade-offs between Cost, Latency, and Quality.

In AI systems, you can't maximize everything — you must choose what matters most for each situation.
💰 CostToken costs, API calls
How much $$$ to run?
⏱️ LatencyResponse time
How fast is it?
✨ QualityAccuracy, relevance
How good is it?

2️⃣ Why This Matters (AI / Agent Context)

🎯 Real decisions you'll make:

• Model Selection: GPT-5 ($1.75/1M) vs GPT-5-mini ($0.25/1M) — when is quality worth 7× cost?

• Reasoning vs Chat: Using o3/R1 ($15/1M) for deep logic vs GPT-5-mini ($0.25/1M) for basic summaries?

• Batch vs Stream: Process 100 items at once (efficient) or one-by-one (responsive)?

• Caching Strategy: Prefix caching (90% discount) vs compute every time (latency cost)?

• Token Optimization: Long comprehensive prompts vs short efficient ones?

• Retry Budget: How many retries before you give up (cost vs reliability)?
💡 The Optimization Mindset: There's no "best" — only "best for this situation." Every choice has trade-offs!

5️⃣ Logical Flow (Optimization Patterns)

Smart Model Selection

GOAL: Use the cheapest model that works STEP 1: ESTIMATE COMPLEXITY Check query for: - Technical terms → higher complexity - Multi-step reasoning → higher complexity - Simple factual → lower complexity complexity_score = word_length × factor + keyword_bonus STEP 2: ROUTE DECISION IF complexity_score > 0.95: → Use o3 / DeepSeek-R1 (Infinite Reasoning) ELSE IF complexity_score > 0.8: → Use GPT-5.2 / Claude 5 Sonnet (High-IQ Lead) ELSE IF complexity_score > 0.4: → Use GPT-5 mini / Claude 4.5 Haiku (Standard Agent) ELSE: → Use GPT-5 nano / Gemini 3 Flash (Sub-cent Extreme Scale) STEP 3: BUDGET OVERRIDE IF budget_sensitive = true AND complexity < 0.9: → Push to nano/mini models

Token-Aware Context Management

GOAL: Fit relevant context within token budget GIVEN: - max_tokens = 4000 - system_prompt = 200 tokens (fixed) - query = 50 tokens (fixed) - available for context = 4000 - 200 - 50 - buffer = 3650 tokens STEP 1: RANK DOCUMENTS For each retrieved document: - Calculate relevance score (cosine similarity) - Calculate token count STEP 2: GREEDY SELECTION selected_docs = [] remaining_tokens = 3650 FOR each doc in order of relevance (highest first): IF doc.tokens <= remaining_tokens: selected_docs.add(doc) remaining_tokens -=doc.tokens ELSE: BREAK (no more room) RESULT: Most relevant docs that fit in budget

Caching Strategy

GOAL: Avoid redundant LLM calls WHEN TO CACHE: - Identical queries (exact match key) - Similar queries (semantic similarity > 0.95) - Frequent queries (query count > threshold) CACHE LOGIC: cache_key = hash(query.lower().strip()) IF cache_key in cache: IF cache[cache_key].age < TTL: RETURN cached response (free!) ELSE: DELETE stale entry # Cache miss - call LLM response=call_llm(query) cache[cache_key]=(response, timestamp) RETURN response CACHE METRICS TO TRACK: hit_rate=cache_hits / total_requests savings=cache_hits × avg_cost_per_call

Batch Processing Logic

GOAL: Trade latency for throughput SCENARIO: Process 1000 items OPTION A - SEQUENTIAL (high latency, low throughput): FOR each item: call_llm(item) wait for response Total time: 1000 × avg_latency = 1000 × 1s = 1000s OPTION B - BATCHED (lower latency per item): Collect items into batches of 10 FOR each batch: call_llm(batch) # single call, multiple items Total time: 100 × avg_latency = 100 × 1.5s = 150s OPTION C - PARALLEL (fastest, but rate limits): Send 50 concurrent requests Wait for all to complete Repeat until done Total time: 20 × avg_latency = 20 × 1s = 20s TRADE-OFFS: A: Simple, reliable, slowest B: Balanced, some complexity C: Fastest, must handle rate limits & failures

8️⃣ Common Mistakes

❌ Using GPT-5.2 for base routing: Use o3 or Flash for initial intent classification!
❌ Ignoring Prefix Caching: New protocols allow sharing caches across agents — 90% cost savings missed!
❌ Truncating Reasoning Logs: Cutting reasoning steps before verification can lead to hallucinations.
❌ Sequential over Batch: Most 2026 SLAs allow for "Asynchronous-Low-Cost" pools via Batch APIs.
❌ Single-Model reliance: Models now have "Regional Drift"; always maintain multi-cloud fallbacks.

9️⃣ One-Line Summary

💡 Optimization is about making smart trade-offs: route cheap vs powerful models, cache repeated calls, batch for throughput, and always stay within token budgets.
