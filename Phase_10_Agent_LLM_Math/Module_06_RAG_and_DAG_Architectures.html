🔄 Module 06: RAG & DAG Architectures

1️⃣ Topic: RAG & DAG for AI Systems

RAG (Retrieval-Augmented Generation) = Enhancing LLM responses by retrieving relevant external knowledge before generating.

DAG (Directed Acyclic Graph) = A graph structure where flows only move forward (no cycles) — the backbone of AI pipelines and workflows.
📚 RAG Retrieve → Augment → Generate

"Give the LLM relevant context before asking it to answer"
🔀 DAG Directed + Acyclic + Graph

"One-way flow with no loops — always terminates"

2️⃣ Why This Matters (AI / Agent Context)

🎯 RAG & DAG are everywhere in production AI:

• LangChain / LangGraph: Every agent workflow is a DAG of nodes and edges

• RAG Pipelines: Query → Embed → Search → Retrieve → Augment → Generate (a DAG!)

• MLOps (Airflow, Kubeflow): All training pipelines are DAGs

• GraphRAG: Advanced RAG using knowledge graphs for relationship-aware retrieval

• Agentic RAG: Agents that decide when/how to retrieve dynamically
💡 Bottom Line: RAG solves the "LLM doesn't know your data" problem. DAG ensures your AI workflows are reliable and always complete. Together, they power modern AI applications!

4️⃣ Core Concept: DAG (Visual Explanation)

What is a DAG?

DAG = Directed Acyclic Graph

• Directed: Edges have direction (A → B means "A leads to B")
• Acyclic: No cycles — you can't follow edges back to where you started
• Graph: Nodes (vertices) connected by edges

Think: A river that only flows downstream — water never flows back uphill!

DAG Properties

🎯 Deterministic Order Nodes execute in dependency order

B waits for A to finish
✅ Guaranteed Termination No cycles = always ends

No infinite loops!
⚡ Parallelizable Independent branches run together

B and C can run simultaneously

🏗️ Why AI Pipelines Use DAGs

Benefit Explanation Example
Order Guarantee Dependencies respected automatically Embedding must complete before search
No Infinite Loops Workflow always terminates Agent won't get stuck forever
Clear Debugging Know exactly what ran when Trace errors to specific node
Parallel Execution Independent paths run concurrently Query multiple APIs at once
Checkpointing Resume from any completed node Retry from last success

Pattern 4: GraphRAG (Knowledge Graph + RAG)

🕸️ GraphRAG: Adding Relationships

Regular RAG: Find similar documents

GraphRAG: Find similar documents AND their relationships


Example:
Query: "Who is the CEO of the company that acquired TechCorp?"

• Vector search finds: "TechCorp was acquired by MegaCorp"
• Graph traversal finds: "MegaCorp CEO is John Smith"
• Combined context gives complete answer!

📚 RAG Pipeline Logic (Simple Meaning)

Stage 1 — Indexing (One-Time Setup)

• Split documents into small chunks.

• Convert each chunk into a vector embedding.

• Store chunks + vectors in a vector database.

Purpose: Prepare knowledge so it can be searched fast later.

Stage 2 — Query Time (Every User Request)

1️⃣ Embed Query Convert user question
into a vector
2️⃣ Search Find similar chunks
in vector DB
3️⃣ Filter Keep only highly
relevant results
4️⃣ Augment Add context to prompt
using retrieved chunks
5️⃣ Generate LLM creates answer
from that context
🎯 Meaning: Find relevant info → Give it to AI → AI answers correctly!

🔀 DAG Execution Logic (Simple Meaning)

What the DAG Shows

📦 Nodes Workflow is broken
into steps (units)
➡️ Direction Steps follow fixed
direction, no loops
⚡ Parallel Some steps can run
together, then merge

How Execution Works

1. Arrange steps in topological order (correct sequence).

2. Wait for dependencies before running each step.

3. Execute node → store output → move forward.

4. Finish when the end node is reached.
🎯 Meaning: A structured, one-way workflow that runs step-by-step until completion.

🔟 Common Mistakes

RAG Mistakes

❌ Chunk size too large: Retrieves irrelevant content, wastes tokens. Use 300-500 tokens per chunk.
❌ No overlap in chunks: Context breaks at chunk boundaries. Use 50-100 token overlap.
❌ Wrong similarity threshold: Too high = misses relevant docs. Too low = noise. Start at 0.75, tune from there.
❌ Ignoring metadata: Store source, date, category. Filter by metadata before vector search!
❌ Not measuring relevance: Track if users find answers helpful. RAG quality degrades silently.

DAG Mistakes

❌ Creating accidental cycles: If retry logic loops indefinitely, you've broken the "acyclic" promise.
❌ Orphan nodes: Nodes that can never be reached from START are dead code. Remove them!
❌ No termination path: Every conditional branch must eventually reach END.
❌ State not persisting: Ensure state passes correctly between nodes. LangGraph handles this via TypedDict.
❌ Not handling node failures: What happens if a node throws an exception? Add error edges!
