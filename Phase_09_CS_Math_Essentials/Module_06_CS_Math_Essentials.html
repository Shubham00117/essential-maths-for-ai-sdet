3️⃣ Part A: Modular Arithmetic

What is Modular Arithmetic?

Modular arithmetic = "Clock math" — numbers wrap around after reaching a limit.

a mod n = remainder when a is divided by n
a mod n = a - n × floor(a / n)

Example: 17 mod 5 = 17 - 5×3 = 17 - 15 = 2

🕐 Clock Analogy

If it's 10:00 and you add 5 hours: (10 + 5) mod 12 = 15 mod 12 = 3:00

Numbers "wrap around" at 12 — this is modular arithmetic!

Common Modular Operations

Operation Pattern Use Case
Wrap index i % array_length Circular buffer, round-robin
Is even? n % 2 == 0 Parity check
Hash bucket hash(key) % num_buckets Hash table distribution
Cycle detection step % cycle_length == 0 Periodic operations

Logical Flow: Circular Buffer Thinking

CONCEPT: Circular Buffer (Ring Buffer) GOAL: Overwrite oldest data when buffer is full STRUCTURE: - Fixed size array (e.g., size = 3) - head pointer (where to write next) LOGIC: When writing item: 1. Write at position: head 2. Move head: head = (head + 1) % size This causes WRAP-AROUND: head = 0 → write → head = 1 head = 1 → write → head = 2 head = 2 → write → head = 0 ← wraps back! EXAMPLE (size=3, write 5 items: A,B,C,D,E): Write A: buffer[0]=A, head=1 Write B: buffer[1]=B, head=2 Write C: buffer[2]=C, head=0 (wrap!) Write D: buffer[0]=D, head=1 (overwrites A) Write E: buffer[1]=E, head=2 (overwrites B) Final: [D, E, C] ← oldest (C) survived

Round-Robin Load Balancing

CONCEPT: Distribute requests evenly across servers SERVERS: [A, B, C] (3 servers) COUNTER: current = 0 REQUEST ROUTING: Request 1: servers[0 % 3] = A, current = 1 Request 2: servers[1 % 3] = B, current = 2 Request 3: servers[2 % 3] = C, current = 3 Request 4: servers[3 % 3] = A, current = 4 (wrap!) Request 5: servers[4 % 3] = B, current = 5 ... RESULT: A → B → C → A → B → C (cycles forever) KEY INSIGHT: Modulo creates PERFECT cycling!

🧠 CS Math: Modular Exponentiation

Calculating (a^b) % n directly is slow for large numbers.

CS uses the Square-and-Multiply method to do this in O(log b) time.

Used in: Cryptography (RSA), hashing, random number generation

4️⃣ Part B: Recursion & Recurrence Relations

What is Recursion?

Recursion = A function that calls itself with a smaller/simpler input.

Three requirements:
1. Base case: When to stop (prevents infinite recursion)
2. Progress: Each call must move toward base case
3. Self-call: Function calls itself with modified input 
factorial(4)
    └── 4 × factorial(3)
              └── 3 × factorial(2)
                        └── 2 × factorial(1)
                                  └── 1  (base case!)
    
Result: 4 × 3 × 2 × 1 = 24

Each call WAITS for the inner call to return!

Recurrence Relations

A recurrence relation defines a sequence where each term depends on previous terms.

Used for: Analyzing algorithm complexity
Recurrence Algorithm Example Complexity
T(n) = T(n-1) + c Linear search, factorial O(n)
T(n) = T(n/2) + c Binary search O(log n)
T(n) = 2T(n/2) + cn Merge sort O(n log n)
T(n) = T(n-1) + T(n-2) Naive Fibonacci O(2ⁿ) 😰

🎓 The Master Theorem (Simplified)

Used to solve recurrences of form T(n) = aT(n/b) + f(n)

It tells us the Big O complexity by comparing:
• Work done in recursive calls (a subproblems of size n/b)
• Work done in current step (f(n))

Quick reference: If a = b and f(n) = O(n), then T(n) = O(n log n)

Recursive Thinking Pattern

PATTERN: Recursive Document Processing (Common in RAG) GOAL: Process nested documents with depth limit THINKING: 1. WHAT'S THE BASE CASE? → If depth >= max_depth: stop, return truncated result 2. WHAT'S THE RECURSIVE CASE? → Process current document → For each child: recursively process (depth + 1) 3. HOW DO WE MAKE PROGRESS? → Each call increases depth by 1 → Eventually hits max_depth (guaranteed termination) LOGICAL FLOW: process(doc, depth=0): IF depth >= 5: RETURN {content: doc.text, truncated: true} result = {content: doc.text} result.children = [] FOR each child in doc.children: result.children.add(process(child, depth + 1)) RETURN result

Memoization: Fixing Exponential Recursion

PROBLEM: Naive Fibonacci is O(2ⁿ) fib(5) calls: fib(5) → fib(4) + fib(3) fib(4) → fib(3) + fib(2) ← fib(3) calculated TWICE! fib(3) → fib(2) + fib(1) ← fib(2) calculated MANY times! Total calls for fib(5): 15 Total calls for fib(50): 40+ billion! 😱 SOLUTION: Memoization (cache previous results) LOGIC: cache = {} fib(n): IF n in cache: RETURN cache[n] ← O(1) lookup! IF n <= 1: result=n ELSE: result=fib(n-1) + fib(n-2) cache[n]=result RETURN result RESULT: O(2ⁿ) → O(n) 🎉

5️⃣ Part C: Matrix Basics

What is a Matrix?

A matrix is a 2D array of numbers arranged in rows and columns.

Notation: A matrix with m rows and n columns is an "m × n matrix"

Key insight for AI: Neural network layers ARE matrix multiplications! 
Matrix A (2×3):           Matrix B (3×2):
┌           ┐             ┌       ┐
│ 1   2   3 │             │ 7   8 │
│ 4   5   6 │             │ 9  10 │
└           ┘             │11  12 │
                          └       ┘

Result of A × B (2×2):
┌                           ┐
│ 1×7+2×9+3×11 = 58    64  │
│ 4×7+5×9+6×11 = 139  154  │
└                           ┘

RULE: (m×n) × (n×p) = (m×p)
      Columns of A MUST equal Rows of B!

How Neural Network Layers Work

CONCEPT: Dense Layer = Matrix Multiplication + Bias INPUT: Batch of samples, each with features Shape: (batch_size, num_features) Example: (32, 768) = 32 samples, 768 features each WEIGHTS: Learned parameters Shape: (num_features, output_size) Example: (768, 256) = transform 768 features → 256 LOGIC: output = input @ weights + bias input: (32, 768) weights: (768, 256) output: (32, 256) ← each sample now has 256 features THIS IS WHY DIMENSIONS MATTER: (32, 768) @ (768, 256) works ✅ (inner dims match: 768) (32, 768) @ (256, 768) fails ❌ (768 ≠ 256)

Attention Mechanism (Simplified)

CONCEPT: Attention = Which parts of input to focus on THE FORMULA: Attention(Q, K, V) = softmax(Q × K.T) × V STEP BY STEP: 1. Q × K.T (Query times Key-transpose) → Produces "attention scores" → Higher score = more relevant 2. softmax(scores) → Converts to probabilities (sum to 1) → Tells us "how much to attend to each position" 3. × V (multiply by Values) → Weighted sum of values based on attention → Output is context-aware representation WHY TRANSPOSE K? Q shape: (seq_len, d_model) = (10, 512) K shape: (seq_len, d_model) = (10, 512) K.T shape: (d_model, seq_len) = (512, 10) Q × K.T: (10, 512) × (512, 10) = (10, 10) → Each position attends to all other positions!
🧠 Why Matrices Matter for AI:
• Every neural network layer is a matrix multiplication
• Attention (Q×K.T×V) is matrix operations
• Embeddings are stored as matrices (vocab × dimensions)
• Batch processing = processing multiple samples via matrices

6️⃣ Part D: Hashing

What is Hashing?

Hashing = Converting any data into a fixed-size "fingerprint" (hash value).

Key properties:
1. Deterministic: Same input → same hash (always!)
2. Fixed size: Any input → same size output
3. Fast: O(1) to compute
4. One-way: Can't reverse hash to get original (for crypto hashes)

🐦 The Pigeonhole Principle

Theorem: If you have 10 holes and 11 pigeons, at least one hole MUST have two pigeons.

Applied to hashing: Input space is infinite, hash output space is finite → Collisions are inevitable!

Implication: Hash tables must handle collisions (chaining, open addressing)

🔑 Hash for Lookup

hash("user_123") → 847291
847291 % 10 → bucket 1

Used in: dictionaries, caches, databases

🔒 Hash for Verification

SHA256("password") → a1b2c3...

Used in: authentication, file integrity, blockchain

Cache Key Logic

CONCEPT: Content-Based Caching GOAL: Same content = same cache key (even with different formatting) LOGIC: 1. NORMALIZE: Remove case differences, extra spaces "Hello World" → "hello world" "HELLO world " → "hello world" 2. HASH: Generate fingerprint "hello world" → hash → "5eb63bbbe01eeed..." 3. LOOKUP: IF hash in cache: RETURN cached_value ← O(1) lookup! ELSE: compute fresh result cache[hash] = result RETURN result WHY NORMALIZE? Without: "Hello" and "hello" = different cache entries 😢 With: "Hello" and "hello" = SAME cache entry 🎉 → Better cache hit rate!

Duplicate Detection Pattern

CONCEPT: Find duplicates without comparing every pair NAIVE APPROACH: Compare every document to every other Complexity: O(n²) ← too slow for large datasets! SMART APPROACH: Hash-based bucketing 1. Hash first 100 chars of each document 2. Group by hash → documents in same bucket are LIKELY duplicates 3. Only compare within same bucket Complexity: O(n) for hashing + O(small) for comparisons EXAMPLE: doc1: "Python is great..." → hash[:8] = "abc12345" doc2: "JavaScript is..." → hash[:8] = "def67890" doc3: "Python is great..." → hash[:8] = "abc12345" ← same as doc1! Buckets: "abc12345": [doc1, doc3] ← check these for duplicates "def67890": [doc2] ← alone, no duplicates

7️⃣ Part E: Bit Manipulation

What is Bit Manipulation?

Bit manipulation = Working directly with individual bits (0s and 1s).

Why? Extremely fast, memory-efficient, and powerful for flags/permissions.

Bitwise Operators

Operator Symbol Example Result
AND & 5 & 3 (0101 & 0011) 1 (0001)
OR | 5 | 3 (0101 | 0011) 7 (0111)
XOR ^ 5 ^ 3 (0101 ^ 0011) 6 (0110)
NOT ~ ~5 -6
Left Shift << 5 << 1 10 (×2)
Right Shift >> 5 >> 1 2 (÷2) 
Binary representation:
    5 = 0101
    3 = 0011

5 & 3 (AND):     5 | 3 (OR):      5 ^ 3 (XOR):
  0101             0101             0101
& 0011           | 0011           ^ 0011
------           ------           ------
  0001 = 1         0111 = 7         0110 = 6

AND: Both bits must be 1
OR:  Either bit can be 1
XOR: Exactly one bit is 1

Bitmasking Concept

🎭 What is a Mask?

A mask is a binary pattern used to pick out specific bits.

To check if 3rd bit is on: AND with 0100 (the mask)
To set 3rd bit: OR with 0100
To clear 3rd bit: AND with NOT 0100 = 1011

Feature Flags Pattern

CONCEPT: Store multiple boolean flags in a single integer DEFINE FLAGS (each is a power of 2): STREAMING = 1 << 0=0001=1 CACHING=1 << 1=0010=2 LOGGING=1 << 2=0100=4 RETRY=1 << 3=1000=8 OPERATIONS: flags=0 (nothing enabled) ENABLE a flag: flags=flags | flag flags |=STREAMING → flags=0001 flags |=CACHING → flags=0011 DISABLE a flag: flags=flags & ~flag flags &=~STREAMING → flags=0010 CHECK a flag: (flags & flag) !=0 flags & STREAMING → 0010 & 0001=0000 → False flags & CACHING → 0010 & 0010=0010 → True WHY USE THIS? Before: 4 boolean variables=4 bytes minimum After: 1 integer=4 bytes stores 32 flags! Also: Can pass/store all flags as single value

Permission System Logic

CONCEPT: Role-based permissions using bits DEFINE PERMISSIONS: READ = 1 << 0=001=1 WRITE=1 << 1=010=2 EXECUTE=1 << 2=100=4 DEFINE ROLES (combinations): VIEWER=READ=001=1 EDITOR=READ | WRITE=011=3 ADMIN=READ | WRITE | EXECUTE=111=7 CHECK PERMISSION: has_permission(user_perms, required)=(user_perms & required)==required EDITOR checking READ: (011 & 001)==001 → True ✅ EDITOR checking EXECUTE: (011 & 100)==100 → False ❌ ADMIN checking EXECUTE: (111 & 100)==100 → True ✅ REAL WORLD: Unix file permissions (rwx) use exactly this!

9️⃣ Common Mistakes

❌ Negative modulo confusion: -7 % 3 = 2 in Python, but -1 in some languages!
❌ Missing base case: Recursion without termination = infinite loop → stack overflow
❌ Matrix dimension mismatch: A(m×n) @ B(p×q) requires n == p
❌ Using Python hash() for persistence: It changes between runs! Use hashlib for deterministic hashing
❌ Not memoizing recursive calls: Naive Fibonacci is O(2ⁿ) — always cache!
❌ XOR swap in production: Clever but unreadable — just use a, b = b, a
